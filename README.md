# Планировщик производства - Craft Planner

## Версия Unity
**Unity 2022.3.52f1**

## Инструкция по запуску
1. Открыть проект в Unity 2022.3.52f1
2. Открыть сцену `Assets/Scenes/RightVersion.unity`
3. Нажать Play

---

## Краткое описание архитектуры

Проект разделён на четыре слоя:

**Data Layer** — ScriptableObject (ResourceSO, RecipeSO, RecipeDatabaseSO). Ресурсы и рецепты добавляются через данные, без изменения кода.

**Domain Layer** — бизнес-логика. Inventory (управление инвентарём), ProductionPlanner (построение плана), PlanExecutor (выполнение плана с паузой/возобновлением). Все классы не зависят от MonoBehaviour.

**Application Layer** — CraftController. Медиатор между UI и бизнес-логикой.

**Presentation Layer** — UI. InventoryUI, CraftRequestUI, ExecutionUI. Только отображают состояние, не хранят данные.

---

## Описание алгоритма планирования

Используется рекурсивный спуск с обходом зависимостей:

1. Создаётся Snapshot инвентаря (оригинал не изменяется)
2. Проверка циклических зависимостей через DFS
3. Рекурсивный обход дерева рецептов от целевого ресурса к базовым
4. На каждом уровне учитывается наличие ресурсов в инвентаре
5. Расчёт количества запусков каждого рецепта (Ceil)
6. Определение недостающих базовых ресурсов
7. Упорядочивание операций (сначала базовые, потом финальные)
8. Расчёт дельты (изменение инвентаря)

## Инструкция по добавлению нового ресурса и рецепта

### Добавление ресурса
1. В окне Project: правой кнопкой → Create → Craft → Resource
2. Заполнить поля:
   - **Id** — технический идентификатор (например, `"iron_ore"`)
   - **Display Name** — отображаемое имя (например, `"Железная руда"`)
   - **Is Base** — true для базовых ресурсов, false для производимых

### Добавление рецепта
1. В окне Project: правой кнопкой → Create → Craft → Recipe
2. Заполнить поля:
   - **Result** — ссылка на ResourceSO результата
   - **Result Count** — количество за одну операцию
   - **Ingredients** — массив (ResourceSO + количество)
   - **Duration Seconds** — время выполнения одной операции

### Добавление в базу данных
1. Открыть `RecipeDatabase.asset` (Assets/Data/)
2. Добавить рецепты в массив Recipes

## Описание способа обнаружения некорректных зависимостей

**Циклические зависимости** обнаруживаются через алгоритм DFS с отслеживанием стека вызовов:
- При обходе рецептов ресурс добавляется в `visiting`
- Если встречается ресурс, уже находящийся в `visiting` — обнаружен цикл
- В `RecipeDatabaseSO.HasCyclicDependencies()` возвращается путь цикла

**Другие проверки:**
- У базовых ресурсов не может быть рецептов
- У производимых ресурсов должен быть хотя бы один рецепт
- При недостатке базовых ресурсов возвращается ошибка с указанием необходимого количества

## Приблизительная вычислительная сложность

- **Время:** O(N × D), где N — количество уникальных ресурсов в цепочке, D — глубина зависимостей
- **Память:** O(N) для хранения плана и посещённых узлов
- Для тестовых данных (до 20 ресурсов) выполняется мгновенно

---

## Известные ограничения

1. Один рецепт на ресурс (нет альтернативных способов производства)
2. Нет частичного выполнения плана
3. Инвентарь не сохраняется между сессиями
4. Нельзя выполнять несколько планов параллельно

## Возможные направления развития

1. Поддержка нескольких альтернативных рецептов
2. Частичное выполнение плана
3. Сохранение инвентаря между сессиями
4. Отмена выполнения с возвратом ресурсов
5. Визуализация графа зависимостей
